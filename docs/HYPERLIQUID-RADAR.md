# Hyperliquid 异常建仓雷达

规则版本 `hl-radar-1`。公共 BTC/ETH 原生永续数据；不下单、不接私钥，不认定内幕交易。

## 根因与影响范围

CoinGlass 五分钟持仓是存量快照，无法证明首次发现就是新钱包或新建仓。雷达独立订阅公开成交，按 `startPosition + signed size` 重建开仓、加仓、减仓、平仓和反手，再与当前账户仓位逐项核对。旧鲸鱼页面、旧采集频率及 `firstSeen` 返回保持兼容；新增 `positionOpenedAt` 说明 CoinGlass `create_time` 的真实含义。

直接复用现有认证、十进制金额与有效 FX、前端请求队列、SMTP TLS。扩展通知账本/额度、备份、健康与总容量统计；主题路由隔离 `hl-radar:`，现有 BTC/VIX/链上成本通知继续共享原六次额度。新事实模型、原生适配、生命周期和同步分组独立实现，不启动旧鲸鱼采集器。

代码集中在 `internal/datahub/radar_*.go`、`internal/tidal/api_v2.go` 和 `web/src/Radar.tsx`/`radar.css`；Hub 启动、通知、备份、状态与页面导航仅作接线。生产缺陷与验收状态见 `STATUS.md`，独立数据库不代表旧写争用已解决。

## 规则与事实边界

- 单地址 BTC/ETH 公开成交量达到 25 万美元进入核验。16 个分钟槽采用当前分钟及前 14 个完整分钟的保守窗口，窗口起始不足整分钟部分不累计，不会用超过 15 分钟的成交凑门槛。
- 成交量不当成开仓额；只有真实开仓周期、美元名义仓位至少 100 万、与 90 秒内账户快照一致才生成提醒。启动前开仓不追认；平多卖出不等于开空；反手结束旧轮、开始新轮。成交连续性冲突降级，交易 ID 不当排序序号。
- 最近 30 天可见历史最早活动位于七天内且无已知截断，称“查询范围内新近活跃”。年龄无法核验仍可发送大额建仓事实；已见七天前活动则不入选雷达。主从账户只展示公开角色证据，共同 CCTP/交易所通道不推定控制关系。
- 快速资金部署：开仓前 30 分钟可核验外部 `deposit` 合计至少 10 万美元；内部划转独立。资金账本与成交年龄完整度分别保存。
- 集中度：该账户的目标币名义占比至少 80%，总名义／正权益至少五倍。设置杠杆单列，零/负权益为未知。其他账户、其他平台对冲未知。
- 同步组：15 分钟至少三个不同候选地址、同币同向，各至少 25 万美元、合计至少 300 万。按组关联，不认定同一控制人。重点提醒在百万建仓基础上满足同步组，或快速资金＋集中度。
- 金额用 decimal，存原生金额及 FX 时间；缺失、过期 FX 不补 1。无清算价保留 null，异常数字拒绝整次事务。

## 采集、容量、恢复

两条市场订阅 BTC/ETH；额外最多八个活跃地址订阅，最多两个 REST 核验 worker。独立每滚动分钟 600 权重，最大响应 2 MiB、候选 5,000、排队 128、去重 20,000；历史成交最多五页、每页 2,000，资金明细最多保存 200。达到边界记录拒绝、降级或不完整，无法证明全链钱包创建时间。

公开流重连带 1–30 秒退避与 ping，保留最近断流起止；已知活跃地址重新排队，用重叠历史去重核验。未知地址在断线期间完成的开平仓可能漏报，查询断流后不追认全球完整覆盖。老地址核验降到五分钟，新候选优先；队列拥堵和上游 429 均可见。

`radar.sqlite` 是独立 SQLite/WAL。钱包证据/成交保留 30 天，事件/outbox/研究 90 天。512 MiB 子预算计入项目总量，主库页数限制约 480 MiB 为 WAL 留余量。达到容量保护或总项目暂停时拒绝新增事实并暴露健康异常。事件与 outbox 同事务；跨库通知用唯一 ID 幂等导出。

部署备份与 CLI 在线备份包含 radar；恢复时与 research 使用同批备份。启动抑制所有历史待发，已尝试但结果不确定不重发。没有删除/重建旧通知、研究起点或旧鲸鱼数据的迁移。回滚旧版本不删除雷达库；旧全站六次计数会保守包含新批次，需待滚动窗口自然过去，不能清空账本释放额度。

## 页面和本地 API

独立 `#hl-radar` 页面提供筛选、25 条分页、事件证据、钱包时间线、同步组、覆盖、通知状态和前向复盘。过期仓位显示历史快照、当前未知。所有 GET 只读本地，不触发上游。

- GET `/api/v2/hl-radar/events?asset=BTC&side=short&limit=25&before=...`（asset/side 可空）
- GET `/api/v2/hl-radar/wallet?address=0x...`：最近 100 条本地 BTC/ETH 成交与有界资金明细
- GET `/api/v2/hl-radar/status`、`settings`、`study`
- PUT `/api/v2/hl-radar/settings`，严格 JSON `{"emailEnabled":false}`，沿用认证和同源校验
- POST `/api/v2/hl-radar/mail-test`：`{"action":"test"}` 发送真实收件测试；`{"action":"confirm","code":"邮件中的32位验收码"}` 记录实际收件证据，不自动开启提醒。

## 邮件操作与验收

默认独立开关关闭。页面先发送真实测试邮件，再由接收方填写邮件内随机验收码，验证后才可开启。数据库只保存验收码哈希，码一小时有效，每分钟最多一次测试，且测试同样受雷达 6 次/全站 12 次额度约束。SMTP 成功不自动确认收件，结果不确定不自动重发。收件确认绑定 SMTP 收件人，重启保留；更换收件人重新验收。兼容运维已有的可选 `radarReceiptVerifiedAt`（RFC3339）记录，不能以 SMTP 返回成功代填。配置文件留在服务器私有目录，不提交 Git。启用之前、重启积压、历史补采都不补发，重复保存同一开关不移动启用边界。

全站每滚动小时最多十二次 SMTP 尝试，旧主题六次＋雷达六次；失败也计数，事务预占后才发。单轮最多建仓/升级各一次；同批合并，同步成员账本关联同批，邮件按组显示一次。正文列完整地址、代表账户金额、时间、换汇、入金、敞口和未知项；组金额不冒充代表地址的金额。待发超过五分钟过期，发送前平仓抑制。正常条件下门槛至提交目标 60 秒；实际时间全部保留，限流与拥堵不排除，尚需生产分布验收。

## 技术验收与效果研究

测试覆盖仓位转移、反手、重复/冲突、事务失败、百万边界、FX、历史截断、资金类别、零负权益/null 清算、过期快照、主题额度、重启与备份、本地只读接口、队列限额和真实 WS→REST→存储测试路径。隔离浏览器数据仅由 `_test.go` 生成，生产不注入样例。可选公开契约：`TIDAL_RADAR_LIVE_CHECK=1 go test ./internal/datahub -run '^TestRadarLiveReadOnlyContractOptional$' -count=1 -v`，不发邮件不落生产库。

首次核验百万级新建仓时，在同一事务冻结同期 Binance 现货参考价、FX 与证据；后续同样使用 Binance 现货，避免将 Hyperliquid/Binance 基差误算成方向收益。发现价缺失永久保留未知，不阻塞事实邮件，也不事后补价。全量已核验大额开仓为基线，雷达入选为子集；邮件开关不选择样本。同步组取最早发现成员，不挑表现最佳者。15 分钟/1 小时/4 小时/24 小时分别记录方向变化与最大有利/不利波动。定时工作有持久化截止队列，优先最早到期，中断保留待重试；缺行情不补零。历史使用 5 分钟完整 K 线与有效历史小时 FX，首尾不足五分钟区间未覆盖，明确不是精确逐笔最大回撤或可实现收益。

页面最多汇总最近 500 条冻结观察，超限标记部分样本，不宣称全量审查；保留失败、反向、缺行情和等待项。至少 30 天、30 个独立完整事件才显示首轮描述性审查就绪，这不是收益证明。受限资源/真实收件/持续生产观察未完成时必须在 STATUS 留待办。

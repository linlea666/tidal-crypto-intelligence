# V2.5 预警正确性与固定候选验证

目标：评估 BTC 提醒对未来 1–4 小时持续上涨的识别能力。ETH 日常数据不变。没有把金额阈值解释为交易建议或预测胜率。

## 根因、影响与复用

| 根因 | 改动与影响 | 复用决策 |
|---|---|---|
| 旧 Active 同时控制重发与跟踪，解除后丢失生命周期 | `signals.go` 独立扫描未闭合事件；解除不影响后续确认，断流仍按墙钟到期；逾期恢复附处理时间和旧状态，不追认历史确认 | 扩展原状态机、原子事件/通知事务；不改旧触发条件 |
| 一条提醒重复匹配多个突破、滚动报告起点会改变合并边界 | 独立 `signal_events.go` 一对一匹配和 `price_events.go` 持久行情账本；同方向至少间隔4小时；首次历史重建显式标记，不计候选现场样本 | 独立匹配模块；线上/历史共用突破定义和匹配器 |
| 最早一次请求失败导致整个90天任务停用 | `study_requests.go` 按最多1000条拆分，由近及远；失败、完成和未尝试分别展示；老任务原样只读，新研究版本单独创建 | 扩展共享任务队列，保留32个后台任务上限、全局12次/分钟、退避和存储保护 |
| 不同粒度 OI/溢价按相同起始时间覆盖 | `signal_features.go` 只读取有效原生300秒数据，使用区间结束键；不得拿小时收盘替代小时内5分钟事实 | 提取闭合窗口与特征计算供研究/线上共用 |
| 原生小时成交与细粒度聚合存在差异 | 指定案例并列保存两套金额、净差、小时版本及首次获取时间；超过1美元净差标记冲突 | 扩展案例输出，不修饰或对齐上游金额；上游根因仍未确认 |
| 分批研究返回 events:null，页面直接 map 导致白屏 | `Research.tsx` 对研究事件/说明等可缺省数组兼容；不改其他页面 | 小范围兼容修复，属于当前功能正确性缺陷 |

直接复用事实仓库、整数美分计算、认证、限流、缓存、SMTP 传输和备份。候选独立版本 `flow-candidate-2.5.0`；旧 `flow-experiment-2.2.0` 保留。评估版本 `events-2.5.0`。没有调整生产 GC、内存上限或无关挂单/巨鲸逻辑。

## 固定候选口径

观察：滚动1小时主动净买入≥3000万美元并达到此前30天的1小时P90。
强候选：≥5000万美元且≥1小时P95；6000万、8000万、1亿只在历史敏感性对照中计算。
共同要求：买入占比≥55%、1小时量比≥1.5、四段15分钟至少三段净买入、4小时净额为正。基线排除当前小时，保留原有额外一小时间隔，需≥21个有效日期且整体覆盖≥95%。所有窗口须闭合、连续、质量有效。

1小时涨幅超过**触发窗口之前**小时ATR的1.5倍时标记位移偏大，不升强候选；过去4小时已发生区间突破标记跟随。金额是五家现货主动成交差额，不是充值提现或新增资金。合约主动成交、美元OI变化、溢价、各结算周期资金费率和最近已闭合一分钟实际清算仅作有时间标记的背景；缺失留空，不参与加分。美元OI包含价格变化影响，不等同新增开多。CVD不重复计分。

候选首次发现冻结特征，同方向4小时内合并；强候选升级另存时点、数据截止、特征、基线及发现价格，不改写原始记录。到期不续期。确认仍使用原冻结4小时价格区间和两根闭合5分钟K线。

## API 与评估

`GET /api/v2/signals?asset=BTC&rules=flow-candidate-2.5.0` 可筛选；不传 rules 保留全部记录。事件增加 features、strongUpgrade、detectionDelaySeconds、evaluationVersion、lifecycleRepair、confirmedDataThrough，旧字段可读。

`studies` 返回新研究版本及 candidateComparison，含30天开发和30天独立留出、0/5/10分钟延迟、旧规则和价格突破对照、1/4小时中位表现、4小时最大有利/不利波动、提前/跟随/漏报/未匹配计数。研究必须先通过90天严格覆盖与基线门槛；不完整时保持未完成。所有固定候选对照使用共同有效输入和完整未来4小时10分钟窗口；历史发布时间未知，只能说明关联。8/19、9/3、9/18前48至后72小时不计独立留出。完整匹配详情保留在零延迟独立留出，其他历史面板只汇总以限制文档大小。

另外给出5000万候选的合约成交同向、美元OI升/降独立过滤，全部使用合约流量和OI均完整的共同窗口；不参与线上加权。相同提醒数量面板按UTC日取原规则、5000万强候选、价格突破三者最小提醒数，各保留最早到达的提醒；只比较共同有配额日期。这是事后归一的人工审查辅助，必须同时查看全部样本结果，不能称为已验证线上策略。

旧辅助指标消融改为共同非缺失样本，样本不足不评分。前向报告保存旧定义归档；新行情账本冻结合并锚点，防止滚动14天起点变化重新分组。候选从本版本首次观察单独计时，缺采不补零；历史补采不能改写现场合格采样。每条提醒最多匹配一个行情事件。未匹配提醒需等待最多8小时（提醒前后4小时匹配范围及行情后续成熟），尚未成熟单列；未匹配不是交易亏损率。

候选审查门槛：至少14天、最近窗口有效覆盖≥95%、≥30个独立买方行情事件。达到门槛只允许开始人工效果审查，必须比较同等提醒数量下的提前识别及误报，没有自动最优阈值选择，也没有自动认定有效。

## 邮件启用与回退

默认不配置候选授权，观察级永不发邮件。强候选/价格确认各以事件ID和通知种类去重；4小时内归为同一事件。沿用每小时最多6次发送尝试、重启积压抑制、发送结果不确定不重试，并抑制过期或数据截止超过12分钟的待发通知。通知账本为秒精度，重启边界采用包含本秒的保守抑制，避免同秒重启漏过积压保护。

只有样本门槛仍满足、前向报告不超过2小时，并完成效果人工审查和真实收件验收后，才在**服务器秘密SMTP配置**中增加 `dashboardUrl`（HTTPS）及 `candidateApproval`：`studyId`（已完成当前版本严格候选研究）、`rulesVersion`、`evaluationVersion`、`reviewedAt`、`receiptVerifiedAt`、`equalBudgetReviewed:true`、`performanceAccepted:true`。时间必须真实，审查不得早于候选观察满14天。这里的布尔值是人工审查结果，不是程序推断；未验收绝不能填写。邮件正文包含窗口净额、量比、阶段、合约背景、支持/冲突/缺失、截止时间和看板入口。不提交配置或凭据。

撤回候选授权或删除 candidateApproval 即停止候选发送；已有发送结果不清空。停止采集、回退旧稳定镜像均不得重置旧验收起点、补发历史邮件。新版数据库只新增文档/字段，旧版本能读取原规则；行情账本及修复记录保留供审计。

## 验收边界

业务回归覆盖孤立事件确认、断流到期、重启/事务恢复、匹配唯一性、小时值隔离、候选固定阈值和位移、升档冻结/去重、子任务隔离、净额跨粒度冲突、邮件人工门槛、历史共同样本与延迟、旧API。

资源回放仍必须区分本机短测、受限Linux、长回放和生产72小时；任意短测不能替代后两者。历史证据与生产正式发布记录见 STATUS。真实市场14天/30事件和SMTP收件验收无法用测试夹具替代；在完成前候选只做站内观察。

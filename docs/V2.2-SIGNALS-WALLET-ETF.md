# V2.2：资金异动、钱包趋势与 ETF

本版仅处理 BTC、ETH。复用 V2.1 的五家现货、美元换算、交易窗口、认证、限流和前端缓存；不改变已经核对的挂单金额计算。新增内容是实验性异动记录和验证工具，不代表已证实预测价值。

## 数据口径和入口

“大资金动向”包含当前动向、异动预警、历史复盘、钱包趋势四个视图；主导航新增独立“ETF资金”。钱包、Coinbase溢价、OI等辅助指标权重均为0，ETF不参与日内预警。不采集财经日历、新闻、ERC-20或原生BTC大额转账流。

| 基础数据 | 用途 | 刷新 / 有效期 | 来源时间 |
|---|---|---|---|
| 五家现货主动买卖 | 原成交/CVD、实验预警、复盘共用 | 5分钟 / 12分钟；原数据1分钟粒度 | 上游区间起点，闭合后使用 |
| BTC/ETH聚合OI历史 | 合约背景、独立对照 | 5分钟 / 12分钟 | 5分钟区间 |
| BTC Coinbase溢价 | 辅助观察 | 5分钟 / 12分钟 | 5分钟区间 |
| BTC/ETH余额列表 | 各所储备及上游1/7/30天变化 | 1小时 / 150分钟 | 未返回时为retrieval_only |
| BTC/ETH余额历史 | 共同来源的1/3/7/30天变化、案例 | 6小时 / 48小时 | 按实际不规则时点 |
| BTC/ETH ETF流向 | 最新披露日、5/20交易日累计 | 北京时间08:30各一次 / 96小时 | 美国交易日，不是发布时间 |

大单结束/撤销历史从30分钟改为60分钟，其余旧采集不变。全部新增契约通过时常规预算约 **10.94次/分钟**，失败请求也计数，任何滚动60秒最多12次、并发最多2。页面GET不请求上游。历史/研究补采统一排队；成交、OI、溢价历史每次最多1000条，其余原接口沿用原分页限制。ETF首次契约检查允许启动时执行一次，之后对齐08:30。

新增数据集首次响应由同一生产调度器执行契约检查：结构或单位解析失败则不写入、标记failed并停用；网络暂时失败按原退避规则重试。不能因为套餐是Pro就自动认定ETH钱包等接口可用。已通过后若响应异常，保留上次数据及原时间，照常降级，不用模拟数据填充。

官方参考：[聚合主动买卖](https://docs.coinglass.com/reference/spot-aggregated-taker-buysell-history)、[聚合OI](https://docs.coinglass.com/reference/oi-ohlc-aggregated-history)、[余额历史](https://docs.coinglass.com/reference/exchange-balance-chart)、[BTC ETF](https://docs.coinglass.com/reference/etf-flows-history)、[ETH ETF](https://docs.coinglass.com/reference/ethereum-etf-flows-history)。代理的真实授权与返回仍须单独核对。

## 钱包与ETF处理

钱包名称固定为“交易所钱包余额净变化”。它不等于充值总量减去已确认提现流水，更不是主动买卖额。Gate/Gate.io等已确认别名只计一次；重复别名余额冲突停止聚合。每个变化窗口仅比较两端共同有效来源，输出`from/to/hours/venues/excluded/delta/percent`，缺失不填0，24/25小时不会伪装成精确一天。

各所列表的1/7/30天变化保留上游原值；顶部趋势使用共同覆盖独立重算。时间窗口端点与目标相差过远时不提供变化。图形采用中性紫/灰蓝，不把余额流出自动染成“利多”。日级历史不插值成小时或分钟。

ETF按美国股票现金市场的周末和常规假日区分交易日；16:00纽约时间之前为交易日未结束。提前收盘日沿用16:00保守判定，不抢先认定完整。额外临时休市仍以报告状态保守处理。总额与基金明细用十进制定点对账，容差1美元。缺总额、缺基金、合计不一致、未披露均不计入累计。

全零且没有明确最终标志的记录为“零值待确认”；分项正负相抵的真实净零可计入。缺日期显式保留空白，不能跨缺失日凑齐5/20日。最新已报告日与今天区分；上游没有final标志时显示“已报告，可能修订”。基金贡献可逐日展开。缓存读取不改变获取时间。

Coinbase溢价先显示美元价差。原始premium_rate保留，单位在未独立核对前不自动转换百分比；它描述两个报价市场的相对压力，不代表完整的美国/亚洲资金流。

## 实验性预警规则

版本：`flow-experiment-2.2.0`。仅完成5分钟窗口进入判断，使用同一五家现货USD主动买卖基础数据；CVD不另计一票。

| 状态 | 买方条件 | 卖方条件 |
|---|---|---|
| 15分钟突增 | 净额≥P95、买入占比≥55%、3根5分钟净额为正、60分钟净额为正、15分钟量≥中位数 | 净额≤P05、卖出占比≥55%，方向对称 |
| 连续三小时 | 3个完整小时净额为正、最后1小时≥P90、3小时买入占比≥55%、最后1小时量≥中位数 | 最后1小时≤P10，其他方向对称 |
| 价格确认 | 发现后4小时内2根完成5分钟K线均收于冻结4小时高点之上，15分钟成交仍同向 | 收于冻结4小时低点之下 |
| 减弱 | 连续2根5分钟成交反向 | 对称 |
| 到期 | 4小时未确认 | 对称 |

基线每小时重算，使用此前30天、留出当前小时避免混入触发窗口；至少21个日期达到单日95%采样且总样本≥95%。当前3小时成交及4小时价格窗口必须完整、新鲜。基线、当前窗口任一不足时停发，保持原大资金页面90%覆盖的描述逻辑。

条件解除满30分钟后才允许同币种同方向再触发。信号、状态机游标和通知入队在单个SQLite事务内提交。重启建立当前游标，历史补采不回填旧邮件。即使数据断流，未确认事件仍按原时点到期。当前价位、冻结阈值、ATR、基础数据截止时间、发现时间分别保留。

## 事实版本与研究

`research.sqlite`独立存储：压缩事实版本、信号/研究文档、前向5分钟观察、通知与缺口。`FirstFetchedAt`是该版本在本系统首次可获取的保守界限；重复抓取不刷新，修订新增版本，按`FactsAsOf`选择当时可见版本。上游未给发布时间时`PublicationKnown=false`；现在拉回的旧数据只可用于关联分析。

研究创建去重，最多4个活动任务；BTC/ETH的成交/OI/溢价通过统一低优先级队列补采。币安价格历史独立每轮最多1000根，原即时价格任务不变。案例是北京时间2026-08-19、09-03、09-18自然日前48小时至后72小时，并未假定精确拉升起点。案例输出每小时净主动买卖/价格变化及每日共同覆盖钱包变化，缺失部分明确为空；指定案例不计入独立留出成绩。

90天研究按30天基线、30天开发、30天留出，滚动基线只使用触发前数据。以现货成交＋价格为基准，分别考察钱包方向、OI增长、溢价方向、五家已覆盖±1%盘口压力过滤；这些固定过滤器只作对照，不进入线上权重。盘口压力仅使用当时实际记录的完整覆盖摘要，历史缺少时该实验没有样本，不伪造回溯数据。

输出1/4/24小时方向收益、触发前已完成1小时ATR14、24小时先达有利2ATR或不利1ATR、同一根5分钟双触及的无法判定、缺失及超时。比例仅针对明确判定子样本，给出样本数和粗略95%区间，不称策略胜率；增加5/10分钟延迟对照。保留期不足90天、粒度缺失或样本未达标，研究标为不完整，仍可查看已有日级钱包/小时价格，不放宽预警条件。

前向观察按当时可读到的窗口首次写入，不允许后来的补采把缺失改成合格。每小时汇总最近14天实际信号及价格事件：两根闭合K线越过此前4小时区间为价格事件，解除30分钟后重计；早于第一根突破K线开始的提醒才算提前，其后4小时内算跟随。漏报只统计当时窗口合格的机会，未合格窗口另计覆盖。达到14天/95%采样只是观察门槛，仍需足够独立行情样本和人工审阅，不自动调权。

## API与扩展

| 本地接口 | 行为 |
|---|---|
| GET /api/v2/signals?asset=BTC | 信号、基线/窗口质量、辅助观察、邮件配置状态 |
| GET /api/v2/signals/{id} | 冻结阈值、发现/确认/到期、证据 |
| GET /api/v2/wallet-trends?asset=BTC | 余额列表、共同覆盖趋势与逐时点排除项 |
| GET /api/v2/etf?asset=ETH | 日报状态、基金对账、5/20交易日累计 |
| GET /api/v2/studies?asset=BTC | 研究列表与14天前向观察进度 |
| GET /api/v2/studies/{id} | 数据覆盖、案例、固定对照、延迟结果 |
| POST /api/v2/studies | `{asset, from?, to?}`，可省略日期请求最近90天；只排队 |

所有GET在认证后只读本地，沿用查询并发/响应上限、超时与私有缓存。服务内计算直接调用共享模块。新增指标应先登记数据契约/刷新/单位，保存基础事实，再增加派生消费方，不能让页面自行调用上游。

研究事实遵守所选30/90天和512MiB子预算，项目仍为20GB、空闲8GB、巨鲸2GB、大单历史512MiB。单个研究响应最多1MiB，事件详情最多300条，汇总使用全部计算事件。SQLite页上限、WAL检查及容量保护优先于研究完整性，研究满时当前行情仍继续；缺口也记录在主状态库。原生产默认768MiB容器上限不变，长期目标600MiB以新72小时样本为准。

## 邮件配置与交付边界

站内记录无需额外配置。邮件只支持TLS/STARTTLS认证SMTP；可将配置存于服务器`/opt/tidal/mail/smtp.json`，容器只读挂载，由`TIDAL_SMTP_FILE`读取。字段为`host, port, username, password, from, to, tls`，tls取`tls`或`starttls`。实际配置放本地已忽略的`secrets/smtp.json`，不得进入仓库、镜像或工具输出。

异动一次、价格确认一次；持久ID去重，每滚动小时最多6次发送尝试，多项合并摘要。发送前持久标记，SMTP结果不确定或发送中崩溃不自动重复发送；未配置期间及重启之前的积压不补发。预警页显示配置或错误状态。没有可用SMTP配置时，不宣称真实邮件已验收。

# V2.4：双列挂单与临近流动性观察

用户已确认实施。发布前功能检查和资源回放结果记录在 STATUS 与 ACCEPTANCE；本文说明数据契约，不代表72小时运行通过。

## 双列看板

大额挂单采用买单在左、卖单在右。两侧各有交易所、最低美元金额、距参考价范围、排序和50/100条分页。共享币种、当前/历史模式、快照版本和美元线性比例尺。改变一侧条件只重置该侧页码；切换快照同时重置两侧页码。手机显示两侧摘要及买卖切换，保留各自条件。

`GET /api/v2/large-orders?asset=BTC&layout=split` 返回 `bid`、`ask`、共同 `version` 和 `scaleMaxCents`。每侧参数为 `bid_venue/minUsd/distance/sort/offset/limit`，卖侧对应 `ask_`。原单列表接口兼容。比例尺使用两侧完整筛选集合，不随单侧翻页改变；筛选条件不同时显示比较限制。

每侧返回已获取、筛选后、有效数量、金额不可换算/距离未知的筛选排除数、所选快照金额和仍有效金额。无数据或无法换算不是零。页内金额、余量、FX、距离和时长固定于同一快照；最新本地事实只能更新有效状态，不能拼接新金额。所选快照的FX超过有效期会退出有效金额，即使页面仍可查旧金额。

`presenceState/presenceNote` 分开表达来源快照有记录、过期、已改变、本次未返回、覆盖未知、上游结束及上游撤销。新列表没有ID不能证明撤单，降到上游筛选门槛以下也可能消失。上游rawState=2仍为结束，rawState=3才按原始标记展示撤销。代理筛选差异不改变该规则。

大单仍独立，不额外加入普通墙、强度或BTC信号。现货盘口原本包含的大额数量不人为扣除。

## 普通盘口变化

每个交易所独立比较相邻、已前进且间隔不超过5分钟的有效盘口时点。以固定**原始报价区间**及币数量比较，汇率只用于显示坐标；源时间未知、范围不可比或同时间修订不推断减量。同时间修订撤回原变化并建立新比较起点。新快照缺少档位记录不补零、不计算100%撤单率。

新 `liquidity_events` 表保存来源、原币数量两端、原始报价金额、起止时间、首次获取时间、显示坐标和证据备注。与大单身份/生命周期表分开，只共用现有512MiB历史容量保护。达到容量时暂停写细变化并记录 `liquidityGapAt`，最新盘口继续服务。界面回看最近30分钟，细事件至少保留1小时供迟到足迹核对，之后按来源/方向/桶宽保存小时观察计数、缺失计数和最大降幅，小时摘要遵循已有30/90天设置；摘要明确不能恢复逐档轨迹或当作成交总量。上一比较状态只保存各桶的数量摘要，不复制全部历史盘口。本地真实量级预览14分钟产生约5.6MB细事件，已据此增加这项汇总，避免细记录长期积累占满512MiB预算。

默认临近参考价0.3%、强调下降50%，BTC/ETH分别可调；属于展示关注门槛，不是撤单概率或买卖信号。后台保存距参考价1%内的观察及±10%内至少25%的下降，详情/最近变化只读取受限本地结果。API最多取最近30分钟300条候选，界面最近列表最多30条，不宣称覆盖全部变化。原始报价桶可能跨越美元价格桶，详情明确区间及单位。

普通墙默认文字改为“尚无匹配触及／成交证据”。参考价来自币安，靠近不证明其他交易所触及；价格越过旧盘口仍等待盘口更新。近期明显减量、未返回或不可比会暂停综合强度标签，金额和历史分位保留。多个重叠原始区间分别处理，不以一个稳定区间掩盖同所另一处减量。

Binance/OKX现货5分钟足迹只为同所、同方向和重叠价格/时间区间提供背景。不能用五分钟总成交减去两分钟盘口减量来算撤单量。迟到足迹显示“此后补到”及获取时间；不改写事件当时已知时间。其他交易所没有对应足迹时保持证据不足。

所有GET只读取本地，没有新增CoinGlass常驻请求、邮件或策略规则。盘口2分钟、大单5分钟和常规约10.74次/分钟预算保持；滚动60秒12次、2并发限制保持。两个新列使用一个缓存快照，不保存两份全量数据。

## 资源根因及修复范围

旧 `BuildBaselines` 会把30天五家完整小时盘口同时保存在内存，对六个桶宽重复执行精确十进制换算。40秒维护超时后没有进度，每分钟从头重来。旧Linux短回放只放入两小时盘口，且未调用完整维护路径，不能覆盖此负载。累计分配不等于常驻内存，也不能仅凭容器与Go堆差值判断泄漏。

现在按天读取并处理盘口，完成一天保存 `baselineBuild.v24` 检查点；每次维护给基线最多12秒子预算，只有全量完成才发布。相同盘口的美元价格/精确分金额转换只做一次，供六个桶宽复用；保留原逐档取整、时间顺序、来源口径和确定性样本选择。中断重启后继续已完成日期，不发布半成品。

本地30天×10市场×每侧1000档剖析：旧算法40秒超时，期间分配约30130MiB，观察到活动堆峰值449.4MiB；新算法27.2秒完成全量，活动堆约18–27MiB、HeapSys42.4MiB。两段完成工作量不同，不能把累计分配差当等工作量降幅；这也不是生产内存已达标结论。

Linux回放使用1.7核、768MiB容器、Go软限512MiB，包含90天研究事实、30天小时盘口、持续采集写入、完整维护、研究及并发API。短回放与至少5小时15分钟回放分别记录Docker内存、CPU、Go堆、HeapSys、RSS、cgroup文件缓存和剖析。长期运行门槛通过后才发布；生产另开固定版本72小时，不重置V2.3失败记录。

`data-status`和受限健康报告新增 `bookBaseline`，包括完成时间、检查点及错误、变化采样错误/缺口。子预算到期且进度前进是分批处理，持续不推进才视为异常。

## 验证及回退

测试包括独立分页/筛选/共同尺度、财务原算法对账、按天检查点与原基线一致、缺失/过期FX、旧快照失效、原币下降与汇率变化区分、空档不补零、同时间修订、迟到足迹和跨来源隔离、容量保护、在线备份恢复与100次本地查询零上游调用。

迁移只新增表、索引、触发器和有版本的状态，不删除旧字段。发布流程保留升级前SQLite在线备份及上一稳定镜像。普通应用回退使用上一镜像，新增表不被旧逻辑读取；如需完整数据库回退，应停写后从升级前备份恢复，不能复制正在使用的WAL文件。失败回退演练使用隔离环境，不计入生产72小时。

前端检查覆盖1440px、390px、200%等效CSS视口、独立分页/筛选、弹窗键盘退出与焦点返回、现货减量说明及其他页面。尚未通过的项目必须保留待验收状态。

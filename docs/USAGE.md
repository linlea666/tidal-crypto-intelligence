# TIDAL V2.1 看板使用说明

打开交付的 HTTPS 地址，输入独立看板密码。访问地址和密码保存在本机已忽略的 `secrets/access.json`，不要上传这个文件。关闭页面不会停止服务器采集。

## 读懂横向价位柱

1. 选择 BTC 或 ETH。上方红色柱表示卖单，下方绿色柱表示买单，中央标出当前价格。
2. 柱长表示该价格区间的有效美元挂单金额，买卖两侧共用同一线性刻度。默认只展示重点价位，点击“展开全部”可查看筛选范围内其他价位。
3. “价格精度”决定合并多少美元为一档；“价格范围”决定离现价多远；“大额状态最低持续时间”筛选已被连续采样确认的大额状态。BTC全景可看1万至20万美元，但深度未覆盖处不能理解为没有挂单。
4. 点击一根柱子，右侧查看金额等级、采样稳定程度、成交证据和交易所贡献。这三类证据分别展示，不是胜率或价格必然反弹的承诺。
5. 底部查看所选区域的金额变化，单独选择回看范围。进阶热力图可用按钮切换，不影响默认柱状读法。

挂单可以随时改变。断线、覆盖边界或汇率变化导致的减少不会标成确定撤单；区间长期有挂单也不表示始终是同一笔订单。未覆盖、过期和未采集的历史会标记或留空，不用零值补造。

“常见金额 / 较大 / 很大 / 异常大”来自最近30天同类价位的历史金额比较，依次对应低于P80、P80–95、P95–99、P99以上。页面的“约P”是估计分位；至少7天、500个有效同类价位样本后才显示。刚上线或覆盖变更时显示“样本不足”是正常状态。

“大额墙·待验证”表示金额显著、尚无充分触及证据；“出现承接/抛压迹象”和“证据较强”还要求匹配来源的实际成交及随后价格反应。旧盘口被最新价格穿过时显示“等待盘口更新”。盘口约2分钟更新，页面报价每秒更新，两者时间不同。

大额挂单是另外筛出的记录，可能已包含在普通盘口金额中，不能再相加。历史状态未核实的记录只显示结束状态和是否记录到成交，不认定为确定撤单。

顶部的范围买卖总额包含所有返回价位，不随重点列表展开/收起或持续时间筛选改变。单根柱子只代表本档当前挂单存量，不是1小时或1天成交；每家来源时间可在侧栏展开核对。五家在线不表示每个价位均覆盖五家。

## 大资金动向

默认观察最近1小时，可切换4小时、24小时；当前大单默认现价±5%，其价格范围不裁剪全市场成交统计。概况依次读买方/卖方较主动或相对均衡、成交占比与净额、同一闭合窗口价格是否跟随、合约背景。有效分钟不足90%、缺少窗口边界或关键源过期时显示证据不足。

大单事件是相邻采样间发现的余量/累计成交变化，首次发现不把全部历史成交计入本期。买挂单成交属于被动承接，不直接算作主动买入；余量减少或记录消失不等同撤单。历史页的状态筛选若与返回原始状态冲突，会保留原始事实并标记覆盖不完整。逐笔大额成交暂未接入，高级视图只显示K线与已观察挂单持续线，不绘制虚构成交圆圈。

OI是合约背景，不会据“现货卖墙＋OI增加”判断主力开空。CVD、净买卖、足迹和大单成交不重复相加或包装成胜率。

## 其他页面

- 总览：币安即时价格和已完成5分钟K线、买卖墙、成交与合约摘要。USDT价格按有效Kraken汇率换算为美元；报价与盘口各自标明更新时间。
- 成交分析：分现货/合约查看主动买卖、VWAP、CVD、价位成交分布和足迹。主动净买入是主动买入额减主动卖出额，与充值提现不同。CVD显示固定起算点，切换币种、市场或窗口会重新锚定；缺口不补零。足迹保留接口的原始价位区间，不代表五家盘口的全部成交。
- 合约态势：CoinGlass已覆盖交易所的OI、资金费率及实际计费周期、已发生清算。聚合OI不与分交易所OI重复相加；OI和价格同涨或同跌只是市场线索，不能直接推出哪一方真实开仓多少。
- 清算分布：默认按价位的横向强度柱，进阶可看历史热力图。24小时视图自动更新，其他回看范围通过共享队列准备。模型强度、已发生清算、Hyperliquid账户清算参考价分别展示，不相加，模型柱也不是触价必然爆仓的金额。
- 巨鲸：CoinGlass已覆盖的Hyperliquid大仓，默认前50、可切前100及按临近清算排序。成本/清算分布使用全部有效已覆盖大仓，显示覆盖及集中程度，不冒充全球巨鲸榜。当前均价不是最初开仓价；设置杠杆不等于实际杠杆。清算距离基于Hyperliquid标记价格；每5分钟采集、每行来源时间8分钟有效，空清算价保留为空。榜单消失不等于确认平仓。
- 设置与数据健康：查看数据目录、源时间/获取时间、剩余额度、队列、异常与资源预算；设置30或90天保留；管理手工价格标注。

“标注开仓 / 止盈 / 止损”只保存个人计划和盈亏比，不连接交易权限，也不提交订单。可在数据健康页删除标注。

## 历史、更新与维护

服务器优先采集当前数据，利用剩余额度补30天小时级盘口基线。上游权限、可用历史及历史汇率会影响补齐范围。旧自建数据保留独立来源，不混入CoinGlass评级。选择90天表示保留较长的降采样历史，不会生成不存在的数据。

默认分层保留：盘口分钟观察7天、5分钟30天、小时至90天；足迹5分钟7天、15分钟30天、小时至90天；巨鲸明细5分钟快照30天。低频采集不会补造成每分钟都有新样本。查询显示实际保存精度。项目预算20GB，巨鲸明细2GB，磁盘至少保留8GB空闲；空间不足先暂停历史补齐，再清理已完成汇总的旧细数据，必要时暂停细写入并标记缺口。

多个页面共用服务器已采集的数据；刷新页面、打开第二个页面不会逐次调用CoinGlass。钱包详情和未准备的回看范围通过去重队列，状态会显示等待。上游滚动60秒最多12次；本地接口不消耗上游额度，但仍有查询时长、并发和响应大小限制。

更新始终按本地 → GitHub 检查 → 正式 Release → 镜像 → 服务器执行。普通提交、草稿或预发布不会更新生产，发布失败会尝试恢复已成功部署的上一版本。详见 [运维说明](OPERATIONS.md) 和 [验收状态](STATUS.md)。

V2.2在“大资金动向”增加“异动预警、历史复盘、钱包趋势”，并提供独立“ETF资金”。预警先提示成交异常，价格突破后另记确认；基线或当前窗口缺失时显示观察中，不强行判断。钱包显示两端共同交易所的余额净变化，不能当作充值/提现总量，也不能把流出直接理解为看涨。ETF按已报告交易日观察，未披露和零值待确认不会参与累计。

历史复盘创建的任务在后台去重排队，页面查询不消耗上游额度。保留期或历史不足会显示不完整；历史关联、实际提前提醒和行情发生后的跟随提醒分别统计。至少14天观察并不等于策略已有效，辅助指标默认不提高预警等级。站内提醒可直接使用，邮件需配置SMTP，状态在预警页显示。详细规则见 [V2.2说明](V2.2-SIGNALS-WALLET-ETF.md)。

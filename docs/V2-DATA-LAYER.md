# V2 数据层与功能接入

仅 BTC / ETH；个人登录；不执行交易。五家现货为 Binance、OKX（USDT）和 Coinbase、Kraken、Bitfinex（USD）。数据目录见 [data-catalog.json](data-catalog.json)，代码登记入口为 `internal/datahub/types.go` 的 `Registry`。目录来自代码生成，不包含密钥、地址或真实响应。

## 数据流与复用

CoinGlass 代理 → 单一调度器 → 标准化校验 → SQLite 最新快照/日期精度分区 → 共享计算 → 本地 `/api/v2`。Binance 只保留 BTC/ETH 即时价格和已完成5分钟K线；Kraken 提供 USDT/USD、USDC/USD 当前及历史汇率。

| 基础事实 | 共用功能 | 刷新 / 过期 | 单位与口径 |
| --- | --- | --- | --- |
| 10个现货盘口 | 金额柱、来源贡献、范围、历史分位、稳定程度 | 2 / 5分钟 | 基础币数量，价格×数量×FX转USD |
| 10个大额挂单列表 | 大单表、远景发现、创建及变更时间 | 10 / 25分钟 | 原报价数量；与普通盘口不相加 |
| 大额挂单历史 | 结束记录、上游记录成交 | 60 / 120分钟 | 状态未确认者不判定为撤单 |
| 现货/合约主动买卖 | 净买卖、CVD、成交背景 | 5 / 12分钟 | 上游USD；不是充值提现 |
| 三家现货/合约足迹 | 按原价位区间的成交分布、VWAP、验证 | 15 / 35分钟 | BTC/ETH数量、原报价、USDT分别保存 |
| OI / 批量资金费率 | 合约汇总、分所、历史 | 5 / 12分钟；10 / 25分钟 | OI All不与分所相加；费率保留原始周期 |
| 已发生清算 | 时间窗口的多头/空头清算 | 5 / 12分钟 | 已观察USD，时间求和 |
| 清算地图 / model1热力图 | 默认价位柱、历史高级图 | 15 / 35分钟 | 相对强度；不同模型与时间不相加 |
| Hyperliquid大仓 | 前50/100、均价/清算分布、距清算3% | 1分钟 / 每行180秒 | 上游覆盖的百万美元级持仓，不是全球榜单 |
| 按需钱包详情 | 权益、保证金及BTC/ETH仓位 | 请求入队 / 180秒 | 账户级权益保留平台原值，不从两个币种重算 |
| 即时价格 / FX | 距现价、美元换算、标注 | 1 / 15秒；5 / 30秒 | 原报价保留；FX失效不假设1美元 |

默认自动刷新24小时模型；7天、30天通过 POST 去重排队。未到达的数据明确等待；GET永不启动上游调用。当前请求优先，其次按需，最后历史补齐。上游平均常规预算约9.94次/分钟，硬上限任意滚动60秒12次；请求最少错开5.1秒、最多并发2个；失败也计数。额度和任务持久化。429统一冷却，401/403认证错误暂停；更换密钥后恢复认证检查。单个反复失败的按需任务暂停，不无限补采。

## 接口契约

- `GET /api/v2/data/catalog`：数据集、来源、币种、市场、单位、刷新/过期、历史边界。
- `GET /api/v2/data/{id}`：本地最新结果；加 `from` / `to`（RFC3339）、`resolution`（秒）、`limit` 查询历史。最多90天、500行、8MiB；`nextFrom`为下一页游标。
- 业务查询：`overview`、`levels`、`flow`、`derivatives`、`whales`、`large-orders`、`liquidations`、`history`、`candles`。
- `GET /api/v2/data-status`：调度、错误、数据时间、额度、磁盘/内存缓存、规则版本。
- `POST /api/v2/data-requests`：`{dataset, from, to, resolutionSeconds}`，或 `{dataset, range}`，或巨鲸数据集加`address`。同类任务去重；重叠历史合并。32个活动按需任务、128个任务记录上限。
- `/api/v2/stream`：认证后共用本地快照推送。前端组件共用同URL缓存、在途请求和刷新器，退出登录清除缓存。

示例 ID：`book.btc.binance.spot`、`flow.eth..spot`、`oi.btc..futures`、`whales.all.hyperliquid.futures`。空交易所字段保留两个点；不要自行拼接猜测，优先读取目录。

元数据包含 `observedAt`、`fetchedAt`、`timeBasis`、`revision`、`resolutionSeconds`、状态和来源。上游没有来源时间时为 `retrieval_only`；页面显示获取时间，不冒充源更新时间。缓存读取/重新计算不延长时效；派生巨鲸分布继承参与持仓的最早更新时间和输入版本。

认证先于数据缓存和304处理；市场查询响应 `private, no-cache` / `Vary: Cookie` / ETag。读API最多2个并发、8秒查询截止、8MiB响应。长热力图最多720个显示时点、每时点400个价位，超过时要求缩小范围；返回实际保存精度和显示抽样间隔。

## 历史、修正和资源

V1历史在原目录保留，V2位于 `data/v2`，不混入新评级。V1采集 goroutine 不再启动，仅完成旧汇总并按原保留策略清理。

V2使用SQLite 3.51.3（modernc.org/sqlite v1.46.2），集中写入、读连接限额、WAL检查点。相同数据集/源时点/内容去重；同一时点修改覆盖并重新汇总；旧响应只补历史，不回退当前快照。汇总未完成的数据集不能删除细数据，不能拿同分区其他数据集的进度代替。小时上游事实不被局部细采样覆盖。

| 分区事实 | 保留 |
| --- | --- |
| 盘口1分钟实际观察 / 5分钟 / 小时 | 7 / 30 / 至90天 |
| 足迹5分钟 / 15分钟 / 小时 | 7 / 30 / 至90天 |
| 主动买卖、OI、资金费率实际粒度 | 30天；小时至90天 |
| 巨鲸分布分钟 / 明细5分钟 | 30天；分布长期降采样；明细每币种前100 |
| 模型 | 完整最新响应；历史只保存分布摘要，热力矩阵不重复落盘 |
| 钱包详情 | 按需缓存，最多1天最新缓存，不持久化逐次详情历史 |

成交与已发生清算按时间求和；VWAP累加数量/金额后相除；盘口/OI/持仓/模型保留末值和有效样本数，不随时间相加。CVD以所选窗口起点为零基准，缺口断线，数值只含已观察成交。

20GB总预算包含旧数据、WAL、镜像、日志、备份；巨鲸明细2GB、磁盘至少8GB空闲。热数据128MiB、计算缓存32MiB和基线值最多32MiB。内存目标低于600MiB，容器上限768MiB。超预算先停止补历史，清理完成汇总的旧细数据，再暂停细写入；最新结果继续服务，健康页显示缺口。日志按7天和大小共同限制。

后台先建立30天小时盘口基线，再通过共享任务补近期窗口。Kraken小时历史FX覆盖不足时，仅对有对应FX的来源组合评级；小时FX换算属于明确标注的历史近似。不会用今天的汇率填满过去30天。完整缺口范围以逐条事实、汇总有效/期望样本数和任务状态为准，first/last仅表示边界，不等于期间完整。

## 证据规则

同币种、买卖方向、现价距离档、桶宽及覆盖来源组合，在30天固定小时抽样中比较非零价位金额。至少7个自然日、500个同类样本才显示等级。基线使用最多1024个确定性保留样本估计分位，界面标“约P”，不把它作为胜率或精确全量统计。

P80以下常见；P80–95较大；P95–99很大；P99以上异常大。大额持续只在P95以上状态连续被新盘口采样确认时累计，超过3分钟观察缺口则中断；30分钟出现比例按时间加权。交易所覆盖改变会形成不同样本组。

成交证据要求挂单先出现、后有对应来源的已完成足迹；仅Binance/OKX同时属于现货盘口与足迹覆盖，Bybit足迹不能验证其他交易所的墙。使用当时存储的FX换算；随后两根5分钟K线有利收盘、反向主动成交达到当前墙5%且BTC至少10万美元/ETH至少5万美元，才满足成交与反应条件。再同时满足P95、30分钟80%、至少三家贡献，才能标“证据较强”。这是明确的初始规则，尚未经过收益率回测。

盘口约2分钟采样，不能确认采样间发生的撤单、补单或同一笔订单身份；足迹也不能还原隐藏单。来源过期、FX失效、价格穿过旧快照时降级，不继续宣称有效支撑。

## 新功能接入

1. 从目录确认已有事实、时间范围、单位和来源覆盖。
2. 已有数据足够时，新增纯查询/派生函数；禁止在页面GET或计算函数中调用上游。
3. 真正新增事实时，先注册标准化器、调度预算、保留/汇总规则、有效期和缺失语义，再接入队列。
4. 加入金额/单位、重复修正、乱序恢复、过期及额度复用测试。`TestGetReadsNeverSpendQuotaAndConcurrentRequestsCoalesce`覆盖100次GET零上游调用和并发请求合并。
5. 修改规则版本后重新生成派生结果；保留来源事实才能重算，已删除精细数据无法从小时汇总恢复。

真实接口样本只放忽略目录 `secrets/v2-probes`；可设置 `TIDAL_PROBE_DIR` 执行私有响应契约测试。公开仓库仅含合成测试输入，不向生产注入模拟行情。代理密钥只通过服务器secret文件加载；服务保持单用户，未启用付费原始数据公开下载或转售。代理授权范围若变更，需再核对允许的保存/分发范围。

# V2.10 大额挂单价格区域

## 根因与边界

原页面面向单条订单和分页检索，缺少按价格区域的完整聚合；远离现价的极大挂单会占据首屏，数量和来源要逐条展开。旧热力图在没有选择单一价格时仍沿用单点覆盖条件，导致有历史数据但来源数为零。

本版默认 BTC／ETH 现货价格区域，原双列明细保持独立买卖筛选、分页、结束记录和冻结快照行为。不改变普通盘口强度分位、巨鲸成本、清算模型、BTC资金信号、研究规则或邮件。来自 `origin/main` 的隔离工作树，不包含 `codex/alert-reliability` 上未合并的预警修复。

## 复用与影响范围

- 直接复用采集调度、身份与生命周期、十进制计算、现有FX、认证客户端及ECharts，不新增上游请求。
- 扩展 `largeViewAt` 允许使用共同时间；短暂占用现有写锁捕获价格、FX、订单及结束状态，等待锁遵循查询取消。历史读取在释放锁后完成。冻结视图支持原有字符串时间和未编码的时间值，旧接口行为不变。
- 独立区域算法和实际采样历史，不套用普通盘口历史分位。单元中心规则与旧floor桶互不替换。
- 分片读取复用流式仓库，新增可选的“每显示时段最后一帧”SQL抽样。现有 `Visit` 不抽样。
- `LargeOrderZones` 组合新页面、原明细和进阶历史；共享页面标题仅对大额挂单隐藏另一套实时价格／普通盘口覆盖提示，防止与冻结大单快照混淆。

## 金额、时间与证据

默认附近±10%、4小时已闭合成交观察；BTC每档250美元，ETH每档10美元。以半开区间 `[中心-step/2, 中心+step/2)` 分档，十进制换算后归桶。先按订单实际美元价格判断参考价上下，再聚合各侧。跨参考价的价格档明确标示，不能把相邻卖单区间之间的空白涂成连续阻力。

完整有效记录参与聚合，不受原明细50／100条限制。每笔先换算至美分，区域和交易所合计按同一美分规则对账；币数量用十进制字符串保留。查询最多5000条大单，超过返回可见错误。每侧金额前三与距离最近三处合并去重，默认价格排序；两侧共享全部区域的最大美元线性尺度。

候选只表示已获取大单的最大集中区，没有综合分数、支撑成功率或已确认箱体。来源创建至来源快照为跟踪跨度；本地首次观察另列，均不证明数量一直不变。

当前页每15秒从本地读取并整体替换响应。版本为完整响应摘要；包含参考价、价格／FX时点、各来源获取时间、独立成交窗口与覆盖。冻结保留原始金额和汇率，超过最早价格／FX／来源到期时间则灰显并说明，不把失效说成撤单。参数修改需恢复实时。

成交使用Binance、OKX、Bybit的已闭合5分钟足迹，买／卖币量及报价成交金额分别汇总。按上游价格段中点归档，跨档位及历史小时FX近似均标识；不把一个区间成交假分配成多个精确价位。缺FX不假设USDT=USD。Bybit只作为独立背景。Binance／OKX只有同所原始价格范围且本地已观察过的订单才能显示“同所价位成交背景”；仍不声称该笔被成交。

累计成交沿用事件差分：首次累计不归入当前窗口；跨窗口的差分单列不确定；修正撤回旧增量。当前区域内订单最近可用的原币数量差分单独展示各自时间界限，不表示完整资金净流入，也不把减少推定为撤单。结束／撤销历史有延迟或缺段时，覆盖保持不完整。

## 接口

- `GET /api/v2/large-order-zones?asset=BTC&step=250&range=10&hours=4`
- `GET /api/v2/large-order-zones/history?asset=BTC&step=250&range=10&period=7d&layer=book`
- 历史 `layer=orders` 可加 `order=<canonical-order-key>` 查看单笔实际采样。
- 现有 `large-orders` 保留。

当前响应含 zones、sources、trades、supportId／resistanceId、共同version和expiresAt。来源失效、无参考价及未知金额不转为零。小时窗口只允许1／4／24；范围1–30%；精度使用该币既有档位。

历史支持24小时／7天，普通盘口与大单独立。原始盘口保存粒度5分钟，大单采集目标5分钟；显示分别取每5／30分钟最后一次实际来源快照，绝不跨时点累加存量。单元字段为 `[中心美元价, 买0卖1, 美分, 原币数量字符串, 贡献来源位掩码, 覆盖来源位掩码]`，按响应venues映射。覆盖分时点、来源、价格单元计算；提供每所实际采样时间、边界及部分状态。纵轴保留空价格档，不压缩中间空档。

K线分别为15分钟／4小时，使用已保存5分钟K线及同期FX换算。基础K线有缺口则整根不显示；小时FX标注近似。单笔轨迹只从真实采样开始，未返回记录或超过7.5分钟采样间距会断开。连接相邻采样不证明其间数量不变。

历史最多400个价格档、100000个来源单元，沿用8秒查询、8MiB响应与32MiB视图缓存上限；超限可缩小范围或增大精度。历史只读，不触发补采。

## 存储、恢复与发布

`hub.sqlite` 新增 `order_zone_samples` 和独立计量表。每次成功的当前列表观察压缩保存最小订单字段和当时有效FX；没有FX仍保留原币记录，美元视图留缺口。完整列表未变化也记录实际观察，结束事件不能补造上线前轨迹。重试同一来源／毫秒时间幂等，乱序观察不能倒退最新数据。

最多7天、64MiB，包含在原512MiB大单预算中。预算紧张仅裁剪新历史，原生命周期记录优先；全局写入暂停时仅记录缺口状态。单份压缩观察最大1MiB，清理按有限批次进行；容量裁剪后实际可用起点缩短，并显示覆盖缺口。原有备份包含新表、触发器与计量，重启继续；回滚不删除任何新增事实，旧视图不读取新表。

发布保持本地 → GitHub检查 → 主分支 → 稳定Release → 不可变镜像部署。受限回放仍为1.7核、768MiB，目标600MiB，不扩大服务资源。短回放、线上初验与连续72小时验收分开记录于STATUS；新历史不足7天是预期冷启动状态，不能记为历史完整。

## 验收方法

`order_zones_test.go` 覆盖534条跨分页集合、USDT/USD换算后分桶、BTC／ETH边界、来源对账、候选并集、旧快照、终态排除、累计跨窗与修正、历史不回填、重复记录、7天清理、共享预算优先级、重启／备份、时点抽样不累加、覆盖计数、取消及100次GET调度不变。

浏览器人工环境仅由 `TIDAL_ORDER_ZONE_BROWSER=1 go test ./internal/tidal -run '^TestOrderZoneBrowserServer$' -v -timeout 50m` 启动，监听127.0.0.1:18084，使用临时目录和test文件内示例数据，生产构建不包含。浏览器访问密码仅供此本地测试：`offline-zone-browser-only`。验收桌面1440px／手机390px、来源展开、冻结过期、ETH、历史图层、明细、键盘与缩放；所有合成数据截图需注明离线验收。
